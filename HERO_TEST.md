# Prototype hero foundation

## Setup

The selector now includes **Fire Spell Prototype** as its third entry. Re-run hero
setup to add its assets/kit without resetting Gun or Sword. See `FIRE_SPELL_TEST.md`
for cast rules, configuration and collision/cancellation checks.

1. Stop Play mode, open `Assets/MovementTest.unity`, wait for script import.
2. Choose **Tools > ClassFPS > Set Up Prototype Hero Selection**. Existing health,
   HUDs, lifecycle/spawnpoint, bot, obstacles and targets remain on the shared scene.
   If missing, run the existing health/training setup first.
3. Setup creates three HeroDefinitions, three weapon definitions and three kit prefabs.
   On first creation, existing gun/sword values, visuals and audio are migrated.
   It then removes scene-only gun/sword behaviors, visuals and weapon audio, and
   adds HeroSelection. No unselected weapon instances remain in the scene.
4. Run setup again: assets, tuning and prefab edits are preserved, not recreated.
   Choose **Tools > ClassFPS > Validate Prototype Hero Assets** to check IDs and
   kit/definition references. Setup also validates before converting the scene.
5. Enter Play mode. Choose Gun, Sword, or Fire Spell Prototype, then click the
   Game view to capture the cursor. Release that capture click before attacking.
   Selection occurs once per Play session. Stop/restart Play to choose the other.

Until selected, the cursor stays released, movement/look/gravity and combat are
blocked, and player damage is blocked. Bots can still fire; they do not aim at you.
Selection places Player at the existing assigned spawnpoint. No selection is saved
between separate Play sessions, and no in-game weapon/hero switching is provided.

## Where to configure

| Asset | Editable values |
| --- | --- |
| `Assets/Definitions/Heroes/GunPrototype.asset` | Stable ID, name, class, health, movement speed, jump, gravity, kit, optional avatar/icon |
| `Assets/Definitions/Heroes/SwordPrototype.asset` | Same hero settings |
| `Assets/Definitions/Heroes/FireSpellPrototype.asset` | Fire hero health, movement, kit and optional references |
| `Assets/Definitions/Weapons/GunPrototype.asset` | Damage, range, cooldown, magazine capacity, reload duration, automatic reload |
| `Assets/Definitions/Weapons/SwordPrototype.asset` | Damage, reach, cooldown, attack arc, windup, active duration, recovery |
| `Assets/Definitions/Weapons/FireSpellPrototype.asset` | Damage, aim distance, cast delay, post-release cooldown, speed, radius, lifetime, projectile |
| `Assets/Prefabs/Heroes/GunPrototypeKit.prefab` | Gun visuals, recoil/effects, clips/volume; one fixed HitscanGun |
| `Assets/Prefabs/Heroes/SwordPrototypeKit.prefab` | Sword model, animation poses, clips/volume; one fixed SwordWeapon |

Assets are generated by the Editor command, not hand-written YAML.
Initial Gun stats copy current player health/speed/jump/gravity (normally 100 / 5 /
1.2 / -20). Sword adds 50 health, 1 m/s speed and 0.4 m jump height (normally
150 / 6 / 1.6 / -20). These are editable test differences, not roster balance.
IDs are `prototype.gun` and `prototype.sword`; keep IDs stable when renaming heroes.
Mouse sensitivity remains a player setting, not a hero statistic.

In hero kits, assigned weapon assets are authoritative. Component Inspectors hide
ignored legacy weapon/ammo tuning and point to the asset. No duplicate live overrides
are applied. For legacy test components with no definition, the old component values
still work. Edit definitions before Play for predictable tests: ScriptableObject
edits made through Unity's Inspector during Play can persist. Runtime code only
reads definitions; health/ammo/timers/swing progress live on component instances.

Optional avatar and icon may be null. Model/effects/sound may also be removed from
a kit without disabling its primary weapon. Keep the HeroKit root active with exactly
one enabled weapon, the matching definition, and enabled WeaponAmmo for guns.
Avatar prefabs should contain presentation only, with no extra player/controller/
weapon/audio-listener components. They are parented to the shared Player root.

HeroDefinition reserves optional Secondary Action Prefab and Passive Prefab references.
Both are null for these prototypes and are not executed in this milestone. Future
behavior can be added to the selected kit incrementally; right-click already routes
to Weapon.SecondaryAttack. No secondary/passive mechanics or generic ability engine
have been introduced. Future fuel/status/effect state belongs to actor components.

## Legacy tools

Hero selection owns the loadout. Shooting Test, Sword Test, Gun Presentation and
Player Weapon Audio setup now reject hero mode with an explicit message, rather
than silently adding extra weapons. Edit kit prefabs for hero presentation/audio.
To return deliberately, stop Play and choose **Tools > ClassFPS > Use Legacy Gun Test**.
It removes HeroSelection and reconstructs the legacy gun test using existing commands.
Sword Test may then be used as before (rerun audio setup to bind the new sword).
Definitions/kit assets remain intact. Re-run hero setup to return to selection;
existing definition/prefab edits are retained rather than overwritten by legacy values.

## Gameplay checklist (requires Unity)

- Run setup twice. Confirm one shared player/selector and no gun/sword components,
  presentations or weapon audio before selection. Existing targets/bot/HUDs remain.
- While choosing: WASD, mouse look, R, attacks and F8/F9 must not affect gameplay.
  Cursor must stay usable for the buttons. Try focus loss/return during selection.
- Select Gun: health and displayed max match its hero asset; movement/jump reflect
  its values. Exactly one HitscanGun and WeaponAmmo exist, and no SwordWeapon or
  SwordPresentation exists, even inactive. Gun visuals/pew2, crosshair, held fire,
  R/automatic reload and ammo HUD should work.
- Select Sword in a new session: its different health/speed/jump are visible.
  Exactly one SwordWeapon exists with no HitscanGun/WeaponAmmo/GunPresentation.
  Infinity HUD, Shing, windup/active/recovery, held swings and wall blocking work.
- For both: walk into the bot lane, take damage, die and respawn at least three
  times. Same selected hero, movement values, health maximum, kit and definition
  remain; no duplicate kit/audio/subscriptions appear. Death hides the weapon;
  respawn clears unfinished attacks/reloads and restores full health/ammo.
- Escape/focus loss and capture click must not fire. Holding the capture click,
  holding through death, and the selection click must not become an attack;
  release then press again. Right-click has no prototype secondary ability.
- Kill the bot with each primary in separate sessions. Check target child-collider
  damage, walls, gun ammo spending and once-per-swing sword damage.
- Duplicate a kit asset for a temporary test and remove only visual/audio children;
  assign it to a hero and verify damage still works. Leave optional avatar/icon/
  future slots null and verify selection works. Restore test edits afterward.
- Change hero stats and weapon values before Play, then restart and verify the new
  configuration. Check definition assets do not gain runtime health/ammo/cooldown data.
