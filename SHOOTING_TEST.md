# Shooting prototype

Uses Unity 6000.3.26f1, Input System 1.20.0 (new input backend), and URP 17.3.0.
No package or project-wide settings changes are required.

## Set up the existing scene

1. Return to Unity, stop Play mode, and let the new scripts import. If needed, use Assets > Refresh.
2. Open `Assets/MovementTest.unity` and save any pending movement changes.
3. Run **Tools > ClassFPS > Set Up Shooting Test**. This uses Unity Editor APIs and saves the active scene. It requires the existing Player, Ground, PlatformSmall, PlatformTall, and Wall objects.
4. The command equips a Hitscan Gun child under Player and adds PlayerCombatInput and CombatCrosshair to Player. It creates three targets under Shooting Targets. Running it again reuses these objects and materials rather than adding duplicates.
5. Reusable URP/Lit materials are saved in the existing `Assets/Materials` folder (or `Assets/materials` if no folder exists). Ground is gray, PlatformSmall blue, PlatformTall orange, and Wall purple. Targets are red, green, and yellow.

The scene and material files are created/saved when you run the command; they are not generated by entering Play mode. No scene YAML is edited by the setup script.

## Components and configuration

Ammo support is now available: run **Tools > ClassFPS > Set Up Weapon Ammo HUD**
to configure existing guns and display the counter. See `AMMO_TEST.md` for magazine
tuning, R reload, automatic reload, and death/cursor checks. Gunfire consumes ammo;
reload blocks attacks without triggering firing feedback or audio.

- **FPSController** retains movement and cursor behavior and exposes whether gameplay input is allowed this frame. Keep its Main Camera assignment.
- **PlayerCombatInput**, attached directly to Player, reads new Input System mouse buttons in LateUpdate, after movement/look Update. Assign its Equipped Weapon to a Weapon component. Left-click calls PrimaryAttack; right-click calls SecondaryAttack, which currently does nothing. Holding left-click fires again as soon as the gun cooldown permits. Right-click remains per press.
- **Weapon** is the small shared base for future guns, melee weapons, projectiles, spells, or shields. Its attack context provides the owner and camera aim ray without prescribing hit detection. Its Inspector settings are Damage, Range, and Attack Cooldown. Defaults are 25 damage, 100 metres, and 0.2 seconds.
- **HitscanGun** implements only primary attack. Hit Layers should include walls, ground, and targets; leave its default mask for this scene. It ignores trigger colliders and all colliders in Player's hierarchy, then uses only the nearest remaining surface. A surface without health still blocks the shot.
- **IDamageable** lets other damage recipients accept damage independently of weapons. **TargetHealth** implements it, supports colliders on child objects, and deactivates its own GameObject at zero health. Put health on the target root, with colliders/renderers on that object or descendants. Maximum Health defaults to 100. Re-enabling a target resets its health.
- **CombatCrosshair**, attached to Player, draws a small centered crosshair with no UI assets. A shot briefly expands it and turns it yellow; successful damage turns it red with a center dot. Misses and blocked shots do not show damage feedback. Colors return to white automatically.

To attach manually instead of using the menu: add PlayerCombatInput and CombatCrosshair to Player, create a child GameObject with HitscanGun, assign that component to Equipped Weapon, and add TargetHealth to the root of each test target. Assign URP/Lit materials to obstacle and target Renderers. Do not add a Rigidbody to Player.

## Test in Play mode

1. Click the Game view to capture the cursor. The capture click must not flash the crosshair, damage a target, or fire. Check WASD, mouse look, and jumping still work.
2. Aim at an exposed colored target and click once. Expect red damage feedback. With the default settings, four clicks at least 0.2 seconds apart deactivate a 100-health target, including its child collider and visual.
3. Fire at empty space or the ground. Expect yellow firing feedback and no red damage feedback. Click faster than the cooldown to check rejected shots produce no feedback.
4. From Player's initial position, aim toward the yellow target at (-8, 1, 8), behind the purple wall. The wall must block shots. Walk around the wall to expose the yellow target and verify it can then take damage. Targets use child colliders, exercising parent health lookup.
5. Press Escape. Cursor unlocks/shows; WASD, look, and both attack buttons stop accepting gameplay input. Gravity continues as before. Clicking to recapture must not fire; release the capture click first; a subsequent press/hold should fire. Hold left-click to verify cooldown-paced shots, and release to stop.
6. Right-click while captured: no attack is implemented yet. Disable FPSController during Play mode: the cursor must restore and attacks must stop. Test switching focus away and back, then clicking to resume.
7. Stop and restart Play mode to restore the test targets. Changes to settings made during Play mode are temporary.

Source diff whitespace checks passed. No connected live Unity Editor API tool was available. The project has a Unity lock file, so a separate batch Editor session was not started.
